# /llm_harness/docs/trees/tree_master.txt
/llm_harness (Source of the LLM coding harness: one stdlib Python CLI, the workflow rules it prints, and installers that copy both into ~/.llm_harness)
├── .gitattributes (The harness's merge rules for its committed notes, verdicts, and tokens: notes by note id, verdicts by key, tokens by <account>@<machine> bucket, run by git through a merge driver the harness registers in each clone)
├── .gitignore (Keeps machine-local harness state out of git; .llm_harness/goal.md, notes.md, verdicts.json, and tokens.json stay tracked)
├── CHANGELOG.md (Notable changes per version, newest first; feat, fix and perf commits add their line under Unreleased)
├── harness.py (Declarative patch / probe / search / run / undo / git CLI; reads one payload from stdin per run; git and no-git workspaces)
    ├── # Stage: IO helpers (Byte-exact file IO keeping EOL style, BOM and undecodable bytes; payload decoding with UI-safe sentinels; workspace path guard)
    ├── # Stage: Line-1 header and tree glyphs (Inserts the /<project>/<path> first-line comment with each language's own marker (// # -- <!-- --> /* */), below a shebang, Python coding line, HTML doctype, XML declaration or PHP opening tag; turns ASCII tree connectors into box glyphs)
    ├── # Stage: Scope resolution (Finds Python/Go/JS/TS/Vue and C#/Java/Kotlin/Rust/C/C++ definitions (brace blocks, C# attributes and Allman braces included) and block bounds; resolves Class.method, Parent > # Stage and tree node paths)
    ├── # Stage: Matching (Applies a hunk only where OLD CODE matches exactly once, scope first then file, with indentation-tolerant fallback; prints on-disk excerpts on failure and says when a one-line OLD CODE is only part of a line; a last pass ignores whitespace inside lines, and NEW CODE counts as already applied only when OLD CODE is found nowhere)
    ├── # Stage: Syntax checks and rollback (Compiles Python and formats Go with gofmt -w (spaces pasted from the chat become tabs; only syntax errors roll back), restoring the pre-script file on errors; runs go build and prunes unused imports)
    ├── # Stage: Payload parser (One state machine for every directive; flags malformed hunks; builds a hunk's new code from +++ [LINE EDITS] +++ against its matched OLD CODE; holds the @INIT_DEBUG ledger skeleton)
    ├── # Stage: Executing file operations (Applies hunks, count-locked @TEXT_REPLACE edits and file ops in memory, writes once, checks syntax, prints the scorecard with [COMMENT REMOVED] notes and line-edit [TIP]s; @DELETE_FILE expands folders and globs into journaled per-file deletes, next-step hints and TREE SYNC REMINDER)
    ├── # Stage: Journal and undo (Per-script journal with pre-image snapshots; @UNDO restores snapshots or reverse-applies hunks, for whole scripts or one file (| /path), skipping files another chat holds; a re-paste at a terminal offers replay, undo from that script on for its chat, or execute again)
    ├── # Stage: Git (@GIT_INIT creates the repository with an optional identity and default .gitignore and carries numbering and undo history into git mode, also automatically after a hand-typed git init; status report; pre-flight-guarded path-scoped commits and unpushed-commit folding that restore HEAD on any failure; commits may include .llm_harness/goal.md, notes.md and .gitignore; @GIT_PUSH publishes the branch or one tag, never forced; @GIT_PULL fast-forwards a clean checkout; the footer's UPSTREAM line shows what the remote has that this checkout lacks, fetched quietly; @GIT_ACCOUNT pins the account git signs in with per project (A signs another account in first) and a push or pull names it first; notes and verdicts merge through a git merge driver)
    ├── # Stage: Read-only directives (Workspace file enumeration, directory listings, @XREF dispatch and whole-word text references)
    ├── # Stage: Code graph (optional codebase-memory-mcp backend) (callers / callees / impact through the CBM CLI with a labelled text fallback)
        ├── run_cbm() (One-shot CBM CLI call; CBM keeps every project's index in its per-user cache, so a moved or cloned project rebuilds its index instead of carrying it)
        ├── workspace_stamp() / index_gaps() / print_coverage_note() / ensure_graph_index() (Re-indexes only when source files changed, records the files CBM parsed only partly, and warns on graph answers that could miss links inside them)
        └── graph_xref() (Runs trace_path, resolves shared names, falls back to text matches labelled NOT proven)
    ├── # Stage: File and text search (@FIND by name or glob; @GREP by text or regex with an optional path filter; one glob rule and an optional '| depth N' shared with @LIST_RECURSIVE and @TEXT_REPLACE)
    ├── # Stage: Running commands (@RUN in PowerShell or bash with timeout, process-tree kill and head/tail output, refusing history-changing git; also the TOC, tree, tree drift check, unused-code, scope-references and scope/lines probe printers (Lines and Scope reads feed the inspection log behind [REVISIT] and show the @VERDICT conclusions covering them; @VERDICTS lists them, one per chat per path, with tree descriptions and stale detection; Tree probes overlay <<verdict>> marks; @CAMPAIGN gives a sweep its verdict legend, footer line and [L1-Campaign] rule until @CAMPAIGN_END removes its verdicts), and the call-site search behind callers)
    └── # Stage: Entry point (Machine-local state, harness-assigned script numbers and a merged state save under a cross-process lock, the @SESSION registry with each session's own aim shown first in the footer and @SCOPE write scopes (paths, globs, folders with a depth, or single definitions, # Stage anchors and tree node paths as file#Class.method, file#Class.method > # Stage: Name or docs/trees/tree_*.txt#Node > Path): overlaps refused by line range, file changes inside another session's scope refused, @RUN changes there reported, scope changes announced once to the other sessions, undo kept inside the session, fold blocked; uncommitted work owned per session (release and commit guards, shared-file warning, explicit hand-over); @MESSAGE, @SCOPE_REQUEST and @BRAKE / @BRAKE_ACK between sessions; blocked work remembered under WAITING ON, announced with [UNBLOCKED] when free (the release itself prints [WAKE] with the waiting chats' addresses) and required before @SESSION_END; claim before change enforced (a session changes only files in its own scope or a user grant); the user's --grant, --release, --unbrake and --link commands; each session's chat address, required at a terminal (only web addresses, no skipping; anything typed before a terminal question is discarded), replaced with @CHAT_LINK when wrong, and shown in listings and refusals; clipboard copy at terminals with per-paste, per-session, and <github_account>@<machine> token estimation stored in .llm_harness/tokens.json (token_bucket_key, _normalize_tokens_doc, record_copied_tokens) (auto-copy when focused via Windows foreground check or POSIX/SSH DECSET 1004 focus events; Windows API/PowerShell, OSC 52 over SSH/headless TTY with tmux passthrough, or pbcopy/wl-copy/xclip/xsel), saved run output that replays on an identical re-paste unless the script is @REPEATABLE (read, search and @RUN only), @SIDE scripts outside the numbering, the goal kept in .llm_harness/goal.md so it travels with the project, per-directive and total run timings, a nudge when a script only did git work, @PART i/n so only the last script of a reply prints the standing rules, [CHANGED] and [NEW] rule marks, collapsed rule briefs that the harness expands on a failure or an open debug ledger, the NO GIT HERE line, @REDO of saved scripts, footer with the user's notes, mode-filtered L1 lines and the commands this chat has not used yet (the full list without a session, or with @HELP COMMANDS), @HELP answered from the syntax card (@HELP LANGUAGES from the harness's own comment, header and symbol tables), workspace mode switch, notes (project-wide, or aimed at chosen chats with for <sessions or patterns>), syntax card, handshake and main)
├── README.md (Human guide: why a chat-interface harness, the paste loop, install, sessions, directives, safety model, memory, optional CBM, rules)
├── setup.cmd (Windows installer: copies harness.py and workflow_commands.txt into %USERPROFILE%\.llm_harness with a timestamped backup, offers a CBM install or update, and always ends with a status line and a pause)
├── setup.sh (POSIX installer: same steps as setup.cmd using curl or wget, and installs xclip or wl-clipboard on Linux when missing; a finish handler prints the status and pauses in terminals, NO_PAUSE=1 skips it)
├── /tests (Harness self-tests, run through @RUN)
    ├── brief_rules_test.py (A rule with a brief prints the brief normally and its full text when its condition holds (failed, ledger, sessions, dirty); @HELP L1-<name> prints any rule in full)
    ├── campaign_test.py (A campaign's legend tags verdicts, its footer line and [L1-Campaign] rule show only while it runs, Tree probes overlay verdicts and stale marks, side scripts are refused, and ending it removes only its verdicts)
    ├── chat_link_test.py (A session's chat address, set with --link or @CHAT_LINK (a wrong one is replaced), required at a terminal without skipping, shows in the session list and in refusals involving that session; no question without a terminal)
    ├── claim_test.py (Claim before change: refused outside the own scope, allowed with a claim in the same script or a user grant, unlimited without a session)
    ├── commands_test.py (The footer lists the commands a chat has not used yet, each chat keeps its own record, the full list without a session and with @HELP COMMANDS)
    ├── comments_test.py (A change deleting a Comment line prints [COMMENT REMOVED] with its text; kept Comment lines and ordinary comments are not flagged)
    ├── delete_test.py (@DELETE_FILE on files, folders and globs goes through the journal and @UNDO restores it, binary files included; claims apply per file; undo skips files another chat holds)
    ├── git_mode_test.py (A project without git says NO GIT HERE and leaves out the git rules; after @GIT_INIT each chat is greeted once and the git rule is marked [NEW] once)
    ├── brief_rules_test.py (A rule with a brief prints the brief, and the full rule in its place after a failed change or command or while a debug ledger is open; @HELP L1-<name> prints any rule in full)
    ├── redo_test.py (@REDO reruns a saved script with corrections and extra directives; unknown scripts and corrections that do not match are refused before anything runs)
    ├── tree_check_test.py (Extensionless files and dotfiles are checked as files; a # Stage node needs a real anchor comment, not the same words in a string)
    ├── commit_policy_test.py (Commit messages need type(scope): subject; git.json refuses protected-branch commits and long headers, warns about branch names, and needs a version)
    ├── worktree_test.py (A git worktree runs in git mode, shares numbering with the main checkout, and keeps its own claims and undo journal)
    ├── repo_ops_test.py (@GIT_BRANCH, @GIT_WORKTREE and @GIT_TAG pass one safety guard and the git.json policy: local changes, other active chats, branch names, tag reachability and changelog)
    ├── rename_text_test.py (A @TEXT_REPLACE or @HUNK after a @RENAME in the same script works on the first pass; the rename rewrites the line-1 path header at once)
    ├── token_label_test.py (Token usage is never filed under Credential Manager's placeholder name "Personal Access Token"; real account names pass through)
    ├── tokens_commit_test.py (tokens.json alone is not committed after a script; it is committed along with another memory change and when a session ends; a modified tokens.json alone keeps the git rule folded)
    ├── language_header_test.py (The first-line header uses each language's own comment marker and sits below an HTML doctype, XML declaration or PHP opening tag; the Comment convention is recognised in every marker)
    ├── language_scope_test.py (Definitions and their blocks are found in C#, Java, Kotlin, Rust, C and C++; calls and conditions are not mistaken for definitions; Python, Go and JS forms are unchanged)
    ├── rename_folder_test.py (@RENAME on a folder moves it file by file through the journal, binary files and exact bytes kept; undo restores it; unsafe moves are refused whole; claims apply per file)
    ├── run_all.py (Runs every *_test.py suite in parallel and prints one summary; with a harness path it tests that file, as the GitHub Actions workflow does)
    ├── scope_glob_test.py (A scope glob collides only with files it really matches; a spaced file name stays claimable after deletion)
    ├── name_regex_test.py (@FIND and @GREP | in accept re:<regex> on the path)
    ├── undo_multi_test.py (Several @UNDO lines, comma lists, globs, and '/old -> /new' recovery to another path)
    ├── prune_test.py (Folders emptied by a rename or delete are removed up the chain; __pycache__-only counts as empty; psutil names a holder)
    ├── loop_check_test.py (Three footer-only scripts in a row give LOOP CHECK; anything that does something resets it)
    ├── memory_commit_test.py (Project memory is committed by the harness; protected branches, ignored files and no-git projects are left alone)
    ├── copy_test.py (C or Enter at a terminal copies the run output to the clipboard (including OSC 52 over SSH, tmux passthrough, and DECSET 1004 focus tracking), X or Esc skips, other keys are ignored, a replay or LLM_HARNESS_COPY=auto copies at once; captured output never waits)
    ├── json_atomic_test.py (A state file is never seen empty or half-written while another chat saves it; a refused replace still saves)
    ├── encoding_test.py (A Python program run through @RUN prints Vietnamese correctly even when its streams would default to a legacy code page)
    ├── setup_test.py (setup.sh pulls the latest changes first in a clone and runs a newer setup.sh once; a non-clone or a failed pull still installs; Linux and macOS only)
    ├── deadlock_test.py (Chats waiting on each other's files in a circle, two or three, get DEADLOCK in every footer in it; a plain wait or a released holder does not)
    ├── delegation_test.py (@DELEGATE moves files and a task at once, @RETURN releases them, refusals and 'drop', delegation breaks a deadlock, and a git-mode receiver can commit the sender's work)
    ├── git_push_test.py (@GIT_PUSH publishes the branch or one tag to a remote; never forced, never a protected branch; a rejected push is reported; a raw git push is still refused)
    ├── git_reads_test.py (git tag listings and git stash list/show are allowed through @RUN; creating or deleting a tag and a plain stash are still refused)
    ├── upstream_test.py (The footer's UPSTREAM line sorts incoming files without changing any; @GIT_PULL fast-forwards a clean checkout with a bookmark and refuses a dirty, diverged or upstream-less branch; an unreachable remote stays quiet)
    ├── memory_merge_test.py (notes.md merges by note id, verdicts.json by key, and tokens.json additively through a git merge driver the harness registers; @GIT_INIT writes the .gitattributes lines; incoming memory without them gets a hint)
    ├── quiet_fetch_test.py (The automatic fetch asks Git Credential Manager not to open a window while a fetch inside @GIT_PULL does not; checked with a stand-in git on Linux and macOS)
    ├── git_account_test.py (@GIT_ACCOUNT lists signed-in accounts, pins one in the clone's git config so git hands that username to the credential helper, refuses an account that is not signed in, clears the pin and skips SSH remotes; a pressed number pins at a terminal; a push or pull the user asked for asks once when several accounts are signed in and none is pinned; the footer says why when the automatic fetch cannot sign in)
    ├── hints_test.py (Refusal hints point at the stated reason; a space-separated @SCOPE gets the comma hint; no tree reminder for names the trees already describe)
    ├── undo_file_test.py (@UNDO <script> | /path restores only that file, also across a range; scripts that never touched it are passed over)
    ├── changed_rules_test.py (A rule that changed since a chat last saw it is marked [CHANGED] once; new chats and runs without a session see no marks)
    ├── tip_test.py (A hunk resending a long, mostly unchanged block gets a [TIP] for +++ [LINE EDITS] +++; line edits rewriting most of their block get the reverse tip for NEW CODE; short blocks and small line edits get none; tips never stop an edit)
    ├── concurrency_test.py (Starts many harness processes at once against a temporary workspace and checks that every script got a unique number, the state stayed consistent and every change landed)
    ├── depth_test.py (One glob rule for @FIND, @GREP, @LIST_RECURSIVE and @TEXT_REPLACE, and '| depth N' on each)
    ├── handoff_test.py (Session aims, release and commit guards for uncommitted work, hand-over, shared-file warning, messages, scope requests, the brake and the user's --release / --unbrake, in a git workspace)
    ├── line_edits_test.py (+++ [LINE EDITS] +++: replace, delete and insert by line number inside the matched OLD CODE; refusals for out-of-range, double edits and non-matching blocks; undo)
    ├── matcher_test.py (OLD CODE found anywhere beats NEW CODE in the scope, whitespace inside lines is tolerated, malformed hints fit the problem, # Stage changes remind only where the trees track them)
    ├── notes_scope_test.py (Notes for every chat or aimed at chosen chats and name patterns: footers, listings with audiences, edits that keep or change the audience)
    ├── parser_test.py (@GIT_COMMIT path lists close at the next directive when @END_GIT_COMMIT is missing; Go hunks pasted with spaces are formatted by gofmt and only syntax errors roll back, skipped where gofmt is not installed)
    ├── parts_test.py (@PART i/n: earlier parts leave out the goal, notes and standing rules, the last part prints them, a malformed @PART keeps the full footer)
    ├── repaste_test.py (A re-paste replays without a terminal; at one it asks: Enter replays, U previews and undoes that chat's scripts from there on, E executes again; committed scripts are kept)
    ├── repeat_test.py (@REPEATABLE scripts run on every paste with fresh numbers, ordinary identical scripts still replay, and repeatable scripts cannot change files or carry a number)
    ├── revisit_test.py ([REVISIT] for rereads of unchanged definitions across ranges, scopes, sessions and side scripts; silence for changed code and within one run)
    ├── scopes_test.py (Two sessions with write scopes: overlap refusal, one-time announcements, refused edits into another scope, @RUN alerts, the user's grant, session-limited undo, scope release)
    ├── session_merge_test.py (--merge <from> <into> absorbs a dead or released session's scope, grants, uncommitted history ownership, pinned notes, verdicts, and delegations into an active session)
    ├── symbol_scope_test.py (Scopes on single methods, # Stage anchors and tree node paths: sibling nodes stay free, edits inside an owned node are refused, enclosing parents overlap; folder scopes with a depth)
    ├── text_replace_test.py (Count-locked @TEXT_REPLACE: edits inside a long line, insert and trim, folder-wide import paths, refusals for wrong counts, ambiguity, short or multi-line text, #Class.method scopes, undo and session scopes)
    ├── verdict_test.py (@VERDICT on folders, files and definitions; @VERDICTS with tree descriptions, collapsed children, stale detection and filters; verdicts shown on reads; refusals and clearing)
    └── waiting_test.py (Blocked work from refusals, overlaps and scope requests listed under WAITING ON, the holder told once, [UNBLOCKED] once when free, @SESSION_END refused until done or dropped)
├── workflow_commands.txt (Workflow rules the AI follows; its L1 Rule lines are printed by the harness after every run)
    ├── #* Utility setup (Install checklist and session start)
    ├── #* Turn manifest & standing rules (11-label manifest with Talk and the goal line with the session aim; [L1-Harness], [L1-Sessions])
    ├── #* Optimal code rules ([L1-Scope], [L1-Notes], micro-hunk format)
    ├── #* Tree structure definition (Level-by-level lookup, same-script tree sync, and how the tree and the CBM code graph divide the work)
    ├── #* Git version control & commit rules ([L1-Git Gate], printed for git projects only)
    ├── #* External verification & hallucination gate ([L1-No-Guess], [L1-Evidence])
    ├── #* Knowledge base curation & master registry ([L1-Knowledge])
    └── #* Anti-loop debug ledger & functionality checklist ([L1-Debug])
├── /docs/knowledge (Verified Tech Knowledge Bases)
└── /docs/debug (Active Bug & Checklist Ledgers)
