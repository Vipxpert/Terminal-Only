# /llm_harness/docs/trees/tree_master.txt
/llm_harness (Source of the LLM coding harness: one stdlib Python CLI, the workflow rules it prints, and installers that copy both into ~/.llm_harness)
├── .gitattributes (The harness's merge rules for its committed notes, verdicts, and tokens: notes by note id, verdicts by key, tokens by <account>@<machine> bucket, run by git through a merge driver the harness registers in each clone)
├── .gitignore (Keeps machine-local harness state out of git; .llm_harness/goal.md, notes.md, verdicts.json, and tokens.json stay tracked)
├── CHANGELOG.md (Notable changes per version, newest first; feat, fix and perf commits add their line under Unreleased)
├── harness.py (Declarative patch / probe / search / run / undo / git CLI; reads one payload from stdin per run; git and no-git workspaces)
    ├── # Stage: IO helpers (Byte-exact file IO keeping EOL style, BOM and undecodable bytes; payload decoding with UI-safe sentinels; workspace path guard)
    ├── # Stage: Line-1 header and tree glyphs (Inserts the /<project>/<path> first-line comment with each language's own marker (// # -- <!-- --> /* */), below a shebang, Python coding line, HTML doctype, XML declaration or PHP opening tag; turns ASCII tree connectors into box glyphs)
    ├── # Stage: Scope resolution (Finds Python/Go/JS/TS/Vue and C#/Java/Kotlin/Rust/C/C++ definitions (brace blocks, C# attributes and Allman braces included) and block bounds; resolves Class.method, Parent > # Stage and tree node paths)
    ├── # Stage: Matching (Applies a hunk only where OLD CODE matches exactly once, scope first then file, with indentation-tolerant fallback; prints on-disk excerpts on failure and says when a one-line OLD CODE is only part of a line; a last pass ignores whitespace inside lines, and NEW CODE counts as already applied only when OLD CODE is found nowhere)
    ├── # Stage: Syntax checks and rollback (Compiles Python and formats Go with gofmt -w (spaces pasted from the chat become tabs; only syntax errors roll back), restoring the pre-script file on errors; runs go build and prunes unused imports; runs the user's own per-project check command for other file types, set with --check on this machine, report-only)
    ├── # Stage: Payload parser (One state machine for every directive; flags malformed hunks; builds a hunk's new code from +++ [LINE EDITS] +++ against its matched OLD CODE; holds the @INIT_DEBUG ledger skeleton)
    ├── # Stage: Executing file operations (Applies hunks, count-locked @TEXT_REPLACE edits and file ops in memory, writes once, checks syntax, prints the scorecard with [COMMENT REMOVED] notes and line-edit [TIP]s; @DELETE_FILE expands folders and globs into journaled per-file deletes, next-step hints and TREE SYNC REMINDER)
    ├── # Stage: Journal and undo (Per-script journal with pre-image snapshots; @UNDO restores snapshots or reverse-applies hunks, for whole scripts or one file (| /path), skipping files another chat holds; a re-paste at a terminal offers replay, undo from that script on for its chat, or execute again)
    ├── # Stage: Git (@GIT_INIT creates the repository with an optional identity and default .gitignore and carries numbering and undo history into git mode, also automatically after a hand-typed git init; status report; pre-flight-guarded path-scoped commits and unpushed-commit folding that restore HEAD on any failure; commits may include .llm_harness/goal.md, notes.md and .gitignore; @GIT_PUSH publishes the branch or one tag, never forced; @GIT_PULL fast-forwards a clean checkout (the local tokens.json is set aside and merged back with the incoming counts when the incoming commits change it too, and @GIT_BRANCH does the same around a switch to an existing branch); the footer's UPSTREAM line shows what the remote has that this checkout lacks, fetched quietly; @GIT_REMOTE adds a remote or changes its address (https or ssh, no password or token inside, never removes one); @GIT_ACCOUNT pins the account git signs in with per project (A signs another account in first) and a push or pull names it first; notes and verdicts merge through a git merge driver)
    ├── # Stage: Read-only directives (Workspace file enumeration, directory listings, @XREF dispatch and whole-word text references)
    ├── # Stage: Code graph (optional codebase-memory-mcp backend) (callers / callees / impact through the CBM CLI with a labelled text fallback)
        ├── run_cbm() (One-shot CBM CLI call; CBM keeps every project's index in its per-user cache, so a moved or cloned project rebuilds its index instead of carrying it)
        ├── workspace_stamp() / index_gaps() / print_coverage_note() / ensure_graph_index() (Re-indexes only when source files changed, records the files CBM parsed only partly, and warns on graph answers that could miss links inside them)
        └── graph_xref() (Runs trace_path, resolves shared names, falls back to text matches labelled NOT proven)
    ├── # Stage: File and text search (@FIND by name or glob; @GREP by text or regex with an optional path filter; one glob rule and an optional '| depth N' shared with @LIST_RECURSIVE and @TEXT_REPLACE)
    ├── # Stage: Running commands (@RUN in PowerShell or bash with timeout, process-tree kill and head/tail output, refusing history-changing git; also the TOC, tree, tree drift check, unused-code, scope-references and scope/lines probe printers (Lines and Scope reads feed the inspection log behind [REVISIT] and show the @VERDICT conclusions covering them; @VERDICTS lists them, one per chat per path, with tree descriptions and stale detection; Tree probes overlay <<verdict>> marks; @CAMPAIGN gives a sweep its verdict legend, footer line and [L1-Campaign] rule until @CAMPAIGN_END removes its verdicts), and the call-site search behind callers)
    └── # Stage: Entry point (Machine-local state, harness-assigned script numbers and a merged state save under a cross-process lock, the @SESSION registry with each session's own aim shown first in the footer and @SCOPE write scopes (paths, globs, folders with a depth, or single definitions, # Stage anchors and tree node paths as file#Class.method, file#Class.method > # Stage: Name or docs/trees/tree_*.txt#Node > Path): overlaps refused by line range, file changes inside another session's scope refused, @RUN changes there reported, scope changes and messages kept in the other sessions' footers until their next numbered script (announce_scope_changes), undo kept inside the session, fold blocked; uncommitted work owned per session (release and commit guards, shared-file warning, explicit hand-over); @MESSAGE, @SCOPE_REQUEST and @BRAKE / @BRAKE_ACK between sessions; blocked work remembered under WAITING ON, announced with [UNBLOCKED] when free (kept until the chat's next numbered script) (the release itself prints [WAKE] with the waiting chats' addresses) and required before @SESSION_END; claim before change enforced (a session changes only files in its own scope or a user grant); the user's --grant, --release, --unbrake, --link and --steward commands (--steward switches the opt-in [L1-Steward] rule per project on this machine); each session's chat address, required at a terminal (only web addresses, no skipping; anything typed before a terminal question is discarded), replaced with @CHAT_LINK when wrong, and shown in listings and refusals; clipboard copy at terminals with per-paste, per-session, and <github_account>@<machine> token estimation stored in .llm_harness/tokens.json (token_bucket_key, _normalize_tokens_doc, record_copied_tokens) (auto-copy when focused via Windows foreground check or POSIX/SSH DECSET 1004 focus events; Windows API/PowerShell, OSC 52 over SSH/headless TTY with tmux passthrough, or pbcopy/wl-copy/xclip/xsel), saved run output that replays on an identical re-paste unless the script is @REPEATABLE (read, search and @RUN only), kept as the newest RUNS_KEEP numbered runs and the newest RUNS_KEEP side runs (prune_runs), with a replay, an undo from a re-paste or a refused script ending in the chat's own session lines and one-time messages (show_state_if_missing), @SIDE scripts outside the numbering, the goal kept in .llm_harness/goal.md so it travels with the project, per-directive and total run timings, a nudge when a script only did git work, @PART i/n so only the last script of a reply prints the standing rules, [CHANGED] and [NEW] rule marks, collapsed rule briefs that the harness expands on a failure or an open debug ledger, the NO GIT HERE line, @REDO of saved scripts, footer with the user's notes, mode-filtered L1 lines and the commands this chat has not used yet (the full list without a session, or with @HELP COMMANDS), @HELP answered from the syntax card (@HELP LANGUAGES from the harness's own comment, header and symbol tables; @HELP KB from the shared knowledge library, @KB as its short form, and a footer line naming the technologies on file for the project; @PLAYBOOK prints a planning procedure on demand; @STEWARD asks the user at the terminal to switch the opt-in steward rule (steward_directive); @TAKEOVER asks the user at the terminal to let this chat absorb another chat's work (takeover_directive), the work being the --merge command's, shared as merge_sessions), workspace mode switch, notes (project-wide, or aimed at chosen chats with for <sessions or patterns>), syntax card, handshake and main)
├── /knowledge (Shared library of pitfalls that AIs keep falling into, one file per technology, searched with @HELP KB (only the technologies the project seems to use, judged from manifests, file types and imports, unless named or all) and installed next to harness.py; entries carry id, tags, symptom, trap, fix, verified, versions and replaces or obsolete)
    ├── python-asyncio.txt (to_thread called instead of passed, executor cancellation hangs, run_in_executor keywords, a task nobody references, a polling loop that re-dispatches in-flight work)
    ├── python-core.txt (getattr default evaluated on every call, process_time counts every thread, spawn re-imports the main module, os.rename on Windows)
    ├── polars.txt (unsigned counts wrap, to_dicts and to_pandas memory, NDJSON files that are plain text, pivot cells filled with 0)
    ├── sql.txt (a lookup join without its day bound multiplies rows)
    ├── ag-grid.txt (autoSizeColumns inside size events loops or right after column changes, column virtualisation, destroyed API, flex parent scrollbar, blank mount, JavaScript functions from Python)
    ├── quasar.txt (q-select loading bound to undefined, WebKit blur, menu collapse and filter autofill, dialog unmount emits, full-height in a flex layout)
    ├── chat-interfaces.txt (triple backticks end a code block, URLs are auto-linked in code)
    ├── google-api-python.txt (httplib2 is not thread-safe, 308 on resumable uploads)
    ├── nicegui.txt (page handler timeout, process-local storage, double session middleware, select options cap, spinner paint, rebinding a bound list)
    ├── vite.txt (HMR behind a TLS proxy, absolute API URLs drop cookies)
    ├── vue.txt (router imported by a composable that a routed view imports)
    ├── spa-hosting.txt (a cached index.html points at deleted chunks)
    ├── google-oauth.txt (http callback behind a TLS proxy, https forced on localhost)
    ├── fastapi.txt (large JSON encoded on the event loop, StaticFiles directory fixed at startup, SPA catch-all rejecting dotted paths, FastAPI as a dev-server proxy, webhook handlers that await long jobs)
    ├── docker.txt (container memory read as the host's, PID 1 ignoring SIGTERM, build-cache mounts and pip backtracking)
    ├── discord.txt (interactions must be acknowledged within 3 seconds, delete_original_response removes the whole message, persistent views need timeout=None, custom_ids and add_view)
├── /playbooks (Planning procedures printed on demand with @PLAYBOOK and installed next to harness.py; each starts with a use-when line and stays short)
    ├── intro.txt (a new user: what the tool is, what it gives, what runs by itself, what only the user does, what to do when a feature did not trigger, then one question)
    ├── plan-first.txt (one feature with a few decisions: frame the request first (would another solution change the architecture?), read the tree and impact, answer before coding with a recommendation, a rejected alternative, questions and done-when lines, then a Todo note)
    ├── plan-project.txt (a new project or big redesign: frame the request first, interview, vision, options, decisions, milestones with done-when lines, docs/plan.md, Todo notes for milestone 1 only)
    ├── review.txt (before work is called complete: read the backlog, Unreleased changelog, Todo notes, stale verdicts and ledgers; check every done against evidence; add what is new; report at most 7 items)
├── docs/backlog.md (What is known to be missing, deferred, unverified or worth doing so nothing lives only in a chat; the AI adds a line in the script that leaves something undone, the review playbook reads it before work is called complete, and the owner reorders or deletes lines freely)
├── README.md (Human guide: why a chat-interface harness, the paste loop, install, sessions, directives, safety model, memory, optional CBM, rules)
├── setup.cmd (Windows installer: copies harness.py and workflow_commands.txt into %USERPROFILE%\.llm_harness with a timestamped backup, offers a CBM install or update, and always ends with a status line and a pause)
├── setup.sh (POSIX installer: same steps as setup.cmd using curl or wget, and installs xclip or wl-clipboard on Linux when missing; a finish handler prints the status and pauses in terminals, NO_PAUSE=1 skips it)
├── /tests (Harness self-tests, run through @RUN)

    ├── campaign_test.py (A campaign's legend tags verdicts, its footer line and [L1-Campaign] rule show only while it runs, Tree probes overlay verdicts and stale marks, side scripts are refused, and ending it removes only its verdicts)
    ├── chat_link_test.py (A session's chat address, set with --link or @CHAT_LINK (a wrong one is replaced), required at a terminal without skipping, shows in the session list and in refusals involving that session; no question without a terminal)
    ├── claim_test.py (Claim before change: refused outside the own scope, allowed with a claim in the same script or a user grant, unlimited without a session)
    ├── commands_test.py (The footer lists the commands a chat has not used yet, each chat keeps its own record, the full list without a session and with @HELP COMMANDS)
    ├── comments_test.py (A change deleting a Comment line prints [COMMENT REMOVED] with its text; kept Comment lines and ordinary comments are not flagged)
    ├── delete_test.py (@DELETE_FILE on files, folders and globs goes through the journal and @UNDO restores it, binary files included; claims apply per file; undo skips files another chat holds)
    ├── git_mode_test.py (A project without git says NO GIT HERE and leaves out the git rules; after @GIT_INIT each chat is greeted once and the git rule is marked [NEW] once)
    ├── brief_rules_test.py (A rule with a brief prints the brief, and the full rule in its place after a failed change or command or while a debug ledger is open; @HELP L1-<name> prints any rule in full)

    ├── check_command_test.py (The user's own check command, set with --check and kept on this machine for the project, runs after a change to a file of that type and only reports; a script cannot set it; a failing command rolls nothing back; a clear removes it)
