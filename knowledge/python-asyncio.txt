## py-thread-handoff-eager
tags: to_thread, run_in_executor, executor, freeze, hang, unresponsive, stuck, blocking, event loop
symptom: The event loop freezes during work that was supposedly moved to a thread.
trap: await asyncio.to_thread(heavy()) calls heavy() on the loop thread first and only hands its result to the pool.
fix: pass the callable, not its result: asyncio.to_thread(heavy) or asyncio.to_thread(lambda: heavy(a, b=1)); the same applies to loop.run_in_executor.
verified: tested on Python 3.12 (the call runs on MainThread), 2026-11
versions: all

## py-executor-cancel-hang
tags: run_in_executor, cancel, CancelledError, subprocess, shutdown, atexit, hang, stuck, reload
symptom: A server hangs on reload or shutdown (event loop closed, process and port still alive) after tasks waiting on a thread pool were cancelled.
trap: Cancelling a task that awaits loop.run_in_executor only detaches it; the worker thread and any subprocess it started keep running, and ThreadPoolExecutor joins its threads at interpreter exit. CancelledError is a BaseException, so except Exception does not catch it.
fix: catch asyncio.CancelledError where the executor call is awaited, terminate the child in a finally block (if proc.poll() is None: proc.terminate()), and shut the pool down with pool.shutdown(wait=False, cancel_futures=True). On Windows terminate() reports exit code 1 (not -15), so remember intentional aborts separately instead of reading the code as a failure.
verified: CancelledError and cancel_futures tested on Python 3.12; the hang and the Windows exit code reported from production use, 2026-11
versions: Python 3.9+ (cancel_futures)

## py-run-in-executor-kwargs
tags: run_in_executor, kwargs, keyword, partial, to_thread, TypeError, executor
symptom: A call to loop.run_in_executor with a keyword argument raises a TypeError, or a wrapper silently loses its keyword arguments.
trap: loop.run_in_executor(pool, func, *args) accepts positional arguments only.
fix: bind them first: loop.run_in_executor(pool, functools.partial(func, *args, **kwargs)); asyncio.to_thread(func, *args, **kwargs) does accept keywords.
verified: tested on Python 3.12 (TypeError with a keyword; partial and to_thread both work), 2026-11
versions: all

## py-create-task-reference
tags: create_task, fire and forget, garbage collected, weak reference, background task, disappears, stops midway
symptom: A background task started with asyncio.create_task sometimes stops midway or never finishes, without any error.
trap: The event loop keeps only a weak reference to its tasks, so a task that nothing else references can be garbage collected while it runs.
fix: keep a reference until it is done: tasks = set(); t = asyncio.create_task(coro()); tasks.add(t); t.add_done_callback(tasks.discard).
verified: recalled from the Python documentation for asyncio.create_task, not reproduced here, 2026-11
versions: all

## asyncio-polling-double-dispatch
tags: polling, in-flight, duplicate, dispatch, tick, background loop, workers, double, database
symptom: A background loop that polls a database and starts tasks launches the same work several times, and the number of workers keeps growing.
trap: The next poll runs before the previous tasks have marked their rows as taken, so the query returns the same targets again.
fix: exclude in-flight states in the query, and mark rows as claimed (an atomic update to a "running" state) before starting the task.
verified: reported from production use, 2026-11
versions: all
